# Участие в разработке

## Принципы

1. **Только реальные данные.** Код не должен создавать события, адреса,
   задержки или выводы, которых не было в источнике. Тестовые двойники источников
   допустимы только в `tests/` и никогда не попадают в приложение.
2. **Источник рядом со значением.** У каждого наблюдения есть `DataSource`
   (`observed_process`, `active_probe`, `system_snapshot`, `etw`, `user`).
   Результат проверки Network Intelligence нельзя выдавать за поведение приложения.
3. **Честные выводы.** Правило отделяет наблюдения (достоверность) от гипотез
   (уверенность), перечисляет альтернативы и ограничения. Гипотезы о
   фильтрации/DPI — не выше «низкой» уверенности, пока нет источника, который
   это обосновывает. Политика проверяется тестом
   `crates/ni-diagnostics/tests/rules.rs::confidence_policy_holds_for_all_rules`.
4. **Без активности по умолчанию.** Сеть трогается только проверками, которые
   пользователь запустил вручную, к одной указанной цели. Сканирование диапазонов
   не принимается.
5. **Версионирование.** Изменение формы событий, выводов, отчёта или схемы
   SQLite — новая версия (`EVENT_SCHEMA_VERSION`, `FINDING_SCHEMA_VERSION`,
   `REPORT_SCHEMA`) или новая миграция в `crates/ni-storage/src/migrations.rs`.
   Существующие миграции не редактируются.

## Проверки перед PR

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test
cd apps/desktop && pnpm typecheck && pnpm lint && pnpm test && pnpm build
```

На Windows дополнительно: `cargo clippy --workspace --all-targets -- -D warnings`
и `cargo test --workspace` (тесты реальных таблиц IP Helper, процессов, иконок и
сквозной тест сборщика).

## Новый источник данных

Реализуйте `ni_core::source::SnapshotProvider` (снимки) или `EventProvider`
(события). Ошибки возвращайте как `SourceError` — сборщик покажет их в
хронологии и в охвате сессии. Опишите, что источник **не** видит, в
`docs/observability.md`.

## Новое правило

Добавьте его в `crates/ni-diagnostics/src/rules.rs`, тесты — в
`crates/ni-diagnostics/tests/rules.rs`. Если данных для правила ещё нет,
добавьте его в `planned()` — такие правила не выдают выводов.
