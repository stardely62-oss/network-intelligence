# Network Intelligence

**Сетевая активность конкретного Windows-приложения и диагностика проблем с подключением.**

Выберите приложение, начните диагностическую сессию, воспроизведите проблему — и
получите все адреса и endpoints, которые удалось наблюдать у его процессов,
историю их появления, смены состояний и исчезновения, результаты контрольных
проверок DNS/TCP/UDP и выводы с явно указанными гипотезами и ограничениями.

> ⚠️ **Статус: 0.1, ранняя версия, без релизов.** Код собирается и проходит
> автоматические тесты в CI на Windows (GitHub Actions `windows-latest`, это
> Windows Server, а не Windows 11). Ручная проверка на Windows 11 ещё не
> проводилась, поэтому релиза нет; тестовая сборка установщика доступна только
> как артефакт CI. См. [docs/manual-testing.md](docs/manual-testing.md).

Network Intelligence — самостоятельная программа. Она работает без
[Discord Bridge](https://github.com/stardely62-oss/discord-bridge), без аккаунта,
облака и сторонних API. Будущая интеграция описана в
[docs/bridge-integration.md](docs/bridge-integration.md).

## Что реально работает в 0.1

| Функция | Как сделано |
|---|---|
| Список процессов с путём, PID, временем запуска, иконкой, числом TCP/UDP endpoints | Toolhelp32 + `OpenProcess`/`GetProcessTimes`/`QueryFullProcessImageNameW`, `SHGetFileInfoW` |
| Группировка многопроцессных приложений | по пути исполняемого файла; можно смотреть и отдельные процессы |
| Корректная идентичность процессов | PID **и** время создания; повторное использование PID не объединяет разные процессы; дочерние процессы проверяются по времени создания |
| Процессы без доступа | помечаются «ограничено правами», идентичность только по PID — и это видно в данных и выводах |
| Диагностическая сессия | выбор → запись → маркеры и заметка → остановка; хранится в SQLite |
| TCP endpoints (IPv4 и IPv6) | `GetExtendedTcpTable(TCP_TABLE_OWNER_MODULE_ALL)`: адреса, порты, состояние, PID, время создания сокета (если ОС его сообщает) |
| UDP endpoints (IPv4 и IPv6) | `GetExtendedUdpTable(UDP_TABLE_OWNER_MODULE)`: **только локальные привязки** — без удалённого адреса и без «соединений» |
| Страница «Соединения» | все наблюдавшиеся адреса, включая успешные; группировка по IP и отдельные endpoints; поиск, сортировка, фильтры, копирование IP |
| Хронология | появление endpoint, смена состояния TCP, отсутствие в снимке, процессы (запуск, завершение, повторный PID), ошибки источника, проверки, маркеры; фильтры и выбор интервала |
| Контрольные проверки | DNS (системный резолвер), TCP connect с тайм-аутом, UDP-запрос (STUN, DNS, текст); раздельно IPv4/IPv6; классификация ошибок WinSock |
| Выводы | 8 правил: охват наблюдения, незавершённое рукопожатие, результаты проверок, DNS-ответы в служебные адреса, различие IPv4/IPv6, приложение vs контрольная проверка |
| Экспорт | версионированный JSON; по умолчанию скрываются частные/локальные IP, пути и заметки |
| Хранение | SQLite в `%LOCALAPPDATA%`, миграции, автоудаление старых сессий, полная очистка истории |

## Чего Network Intelligence 0.1 не видит

Это важно для правильного чтения результатов:

- **Это снимки, а не захват пакетов.** Таблицы сокетов опрашиваются с интервалом
  (по умолчанию 1 с, от 250 мс). Соединение, которое открылось и закрылось между
  двумя снимками, не будет замечено. Полной истории соединений 0.1 не даёт.
- Момент исчезновения endpoint — это время снимка, в котором его уже не было,
  а не время закрытия.
- В системной таблице UDP нет удалённых адресов: с кем приложение обменивается
  UDP-пакетами (голос, QUIC), 0.1 **не знает**.
- TCP-сокеты в `TIME_WAIT` обычно принадлежат PID 0 и к приложению не относятся.
- DNS-имена соединений, байты, пакеты, RTT, повторные передачи, TLS/SNI —
  не собираются. Поля для них предусмотрены в модели, но не заполняются.
- Признаки DPI **не определяются**. Правила для этого спроектированы и помечены
  в интерфейсе как «запланировано». Ни тайм-аут, ни RST, ни отсутствие
  UDP-ответа не выдаются за доказательство блокировки.

Событийный сборщик (ETW/WFP) — план версии 0.2: [docs/roadmap.md](docs/roadmap.md).

## Безопасность и приватность

- Работает без прав администратора. Права не запрашиваются; с ними становится
  доступна идентичность большего числа системных процессов.
- Никаких драйверов, перехвата трафика, изменения пакетов, брандмауэра, DNS или
  настроек Windows.
- Ничего не отправляет в сеть, кроме проверок, которые вы запускаете вручную к
  указанной вами цели. Нет телеметрии, аккаунтов, автообновлений.
- Содержимое пакетов, пароли, токены и cookie не собираются — источник 0.1 их не
  видит вообще.
- Данные — в профиле пользователя; есть удаление сессий и всей истории.

Подробнее — [SECURITY.md](SECURITY.md).

## Сборка

Требования: Windows 10/11 x64, Rust stable (≥ 1.88), Node.js 22, pnpm 9,
WebView2 (есть в Windows 11).

```powershell
cd apps/desktop
pnpm install
pnpm tauri dev      # разработка
pnpm tauri build    # установщик NSIS в target/release/bundle/nsis
```

Ядро (без Tauri) собирается и тестируется на любой ОС:

```bash
cargo test            # все крейты, кроме приложения
cargo test --workspace  # на Windows — включая тесты реальных таблиц IP Helper
```

Локальный тестовый сервер для ручных проверок: `cargo run -p ni-probe --example test_server`.

## Структура

```
apps/desktop/            Tauri 2 + React + TypeScript (интерфейс)
apps/desktop/src-tauri/  команды приложения, состояние, запись сессий
crates/ni-core/          модели (версионированные), идентичность процессов, корреляция снимков
crates/ni-windows/       Toolhelp32, IP Helper, иконки (только Windows; на других ОС — «недоступно»)
crates/ni-collector/     цикл сбора сессии, охват наблюдения
crates/ni-probe/         DNS / TCP / UDP-проверки
crates/ni-diagnostics/   правила и выводы
crates/ni-storage/       SQLite, миграции
crates/ni-report/        JSON-отчёт и удаление чувствительных данных
docs/                    архитектура, модель данных, наблюдаемость, интеграция с Bridge, план
```
