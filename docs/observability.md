# Границы наблюдаемости 0.1

## Источник

`windows-iphlpapi-toolhelp` — периодический снимок:

| API | Что даёт | Чего не даёт |
|---|---|---|
| `CreateToolhelp32Snapshot` / `Process32*W` | PID, PID родителя, имя файла, число потоков | время создания, путь |
| `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` + `GetProcessTimes` + `QueryFullProcessImageNameW` | время создания (идентичность), полный путь | для защищённых процессов без прав администратора — ничего |
| `GetExtendedTcpTable(AF_INET/AF_INET6, TCP_TABLE_OWNER_MODULE_ALL)` | локальный/удалённый адрес и порт, состояние, PID владельца, время создания сокета | байты, пакеты, RTT, повторы, RST/ICMP, TLS/SNI, DNS-имя |
| `GetExtendedUdpTable(AF_INET/AF_INET6, UDP_TABLE_OWNER_MODULE)` | локальная привязка, PID владельца | **удалённые адреса**, пакеты, ответы |
| `SHGetFileInfoW` + `GetIconInfo` + `GetDIBits` | иконка файла | — |

## Следствия

1. **Кратковременные соединения могут быть пропущены.** Всё, что открылось и
   закрылось между двумя снимками, невидимо. Интервал по умолчанию 1 с,
   минимальный 250 мс. Фактический максимальный разрыв между успешными снимками
   сохраняется в сессии и показывается в выводе «Охват наблюдения».
2. **Время закрытия неизвестно.** Известно лишь, что endpoint был в снимке
   `last_seen` и отсутствовал в снимке `gone_at`.
3. **UDP — только привязки.** Строка UDP означает, что процесс держит
   локальный порт. С кем он обменивается датаграммами — неизвестно; поэтому
   UDP-строки в «Соединениях» показываются без удалённого адреса и никогда не
   называются соединениями.
4. **`TIME_WAIT` и PID 0.** Закрытые TCP-соединения в `TIME_WAIT` обычно
   принадлежат PID 0 и к приложению не относятся.
5. **PID-only идентичность.** Без доступа к процессу повторное использование
   PID определяется только по смене имени файла; такие наблюдения помечены
   достоверностью «средняя».
6. **Ошибка таблицы ≠ исчезновение.** Если таблица TCP или UDP не прочиталась,
   endpoints этого протокола не объявляются исчезнувшими; ошибка записывается
   как `sourceError`.
7. **Проверки — не приложение.** Результаты `active_probe` показывают, что
   получил Network Intelligence в момент проверки.

## Что видно в интерфейсе

- Охват каждой сессии: источник, интервал, успешные/неудачные снимки,
  максимальный разрыв, число PID-only процессов, последняя ошибка.
- Неудачные снимки отмечены на полосе активности в «Хронологии».
- Нереализованные поля и правила перечислены как «нет источника» /
  «запланировано».

## Особенность Windows: отказ TCP приходит не сразу

Получив RST на SYN, Windows повторяет попытку подключения и сообщает
`WSAECONNREFUSED` только примерно через 2 с (обнаружено тестом CI на
закрытом порту loopback). Поэтому минимальный тайм-аут TCP-проверки в
интерфейсе — 3 с, а вывод о тайм-ауте с меньшим значением содержит это
ограничение. Linux сообщает об отказе сразу.
