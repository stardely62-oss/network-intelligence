# Архитектура

```
┌──────────────────────────── network-intelligence.exe (обычный пользователь) ─────────────────────────┐
│                                                                                                       │
│  React UI (apps/desktop/src)                                                                          │
│   Обзор · Соединения · Диагностика · Хронология · Отчёты · Настройки                                  │
│        │  invoke (фиксированные команды)          ▲ событие "live-status" ≤ 1 раз/с                   │
│        ▼                                          │                                                   │
│  Tauri-команды (apps/desktop/src-tauri)  ─────────┘                                                   │
│        │                                                                                              │
│        ├── ni-collector ── поток сбора ──► SnapshotProvider ── ni-windows (Toolhelp32, IP Helper)     │
│        │        │   TargetTracker (процессы)   Correlator (endpoints → события)                       │
│        │        ▼                                                                                     │
│        │   TickBatch ──► ni-storage (SQLite, одна транзакция на снимок)                               │
│        ├── ni-probe (DNS/TCP/UDP по действию пользователя) ──► ni-storage                              │
│        ├── ni-diagnostics (правила → Finding) ──► ni-storage                                          │
│        └── ni-report (JSON + редактирование) ──► файл из диалога сохранения                           │
└───────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

## Слои

| Слой | Где | Ответственность |
|---|---|---|
| Сбор | `ni-windows` | Чтение ОС: процессы, таблицы TCP/UDP, иконки. Только реальные строки; ошибки — `SourceError`. На не-Windows — `UnavailableProvider`. |
| Нормализация | `ni-core::addr`, `SocketRow::normalized` | IPv4-mapped IPv6 → IPv4, `0.0.0.0:0` удалённого конца → «нет», UDP без состояния, классификация областей адресов. |
| Корреляция | `ni-core::process::TargetTracker`, `ni-core::correlate::Correlator` | Какие процессы относятся к цели (корень, дочерние, тот же файл, перезапуск); endpoint = (протокол, локальный и удалённый адрес/порт, идентичность процесса); появление, смена состояния, исчезновение, эпизоды. |
| Сессия | `ni-collector` | Цикл снимков с заданным интервалом, учёт охвата (успешные/неудачные снимки, максимальный разрыв, PID-only идентичности), статус для UI с ограничением частоты. |
| Хранение | `ni-storage` | SQLite, миграции по `user_version`, полный JSON + индексируемые столбцы, каскадное удаление. |
| Выводы | `ni-diagnostics` | Правила над доказательствами сессии; наблюдения и гипотезы раздельно. |
| Представление | `apps/desktop` | Только чтение готовых данных; таблицы виртуализированы, данные подтягиваются из БД раз в 2–5 с, а не по событию на каждый сокет. |

Ядро (`ni-core`, `ni-collector`, `ni-probe`, `ni-diagnostics`, `ni-storage`,
`ni-report`) не зависит от Tauri и React и тестируется на Linux. Отдельного
крейта `ni-bridge` нет: интеграции пока нет, есть проект
([bridge-integration.md](bridge-integration.md)).

## Идентичность процессов

`ProcessIdentity { pid, created }`, где `created` — FILETIME создания процесса
(`GetProcessTimes`). Правила `TargetTracker`:

- корневой процесс сопоставляется только в первом снимке; если он уже завершился,
  новый владелец того же PID не будет принят за него;
- тот же PID с другим временем создания → событие `pidReused`, старый процесс
  считается завершённым, новый не отслеживается (если он не подходит по
  другим правилам);
- дочерний процесс: `parent_pid` — отслеживаемый процесс **и** ребёнок не старше
  родителя (Windows не обновляет `parent_pid` после завершения родителя,
  поэтому «ребёнок» с переиспользованным родительским PID отбрасывается);
- без доступа к процессу идентичность PID-only; признаком повторного
  использования PID служит смена имени исполняемого файла; достоверность таких
  наблюдений — «средняя».

Строки таблиц сокетов относятся к процессу по PID **того же снимка**.

## Производительность

- Один снимок: Toolhelp32 + `OpenProcess` на процесс + 4 вызова IP Helper.
  Длительность каждого снимка сохраняется и показывается в UI.
- Запись снимка — одна транзакция SQLite; обновляются только изменившиеся
  endpoints (и `last_seen`/счётчики присутствующих).
- UI получает статус не чаще ~1 раза в секунду, таблицы читает пакетно с
  интервалом 2 с только пока выбранная сессия записывается, рендерит только
  видимые строки (`@tanstack/react-virtual`).

## Расширяемость

- `SnapshotProvider` — периодические источники; `EventProvider` — событийные
  (ETW/WFP в 0.2). Сборщик и хранилище не предполагают, что снимки — единственный
  вход: у событий есть `source`, у endpoint — `source` и `confidence`.
- Новые поля endpoint (DNS-имя, ASN, байты, RTT, повторы) добавляются в JSON
  с `#[serde(default)]`; старые записи читаются без миграции.
- Правила: `Rule` + каталог `planned()` для правил, данных для которых ещё нет.
