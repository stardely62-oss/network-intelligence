# План 0.2: событийный сбор (ETW/WFP) и DPI Detection

## Цели

1. Видеть соединения, которые живут меньше интервала снимков.
2. Получить удалённые адреса UDP, DNS-имена, байты, RTT и повторные передачи.
3. Дать правилам DPI данные, без которых они сейчас помечены «запланировано».

## 1. ETW-сборщик (`ni-etw`, реализует `EventProvider`)

| Провайдер | Данные | Права |
|---|---|---|
| `Microsoft-Windows-Kernel-Network` (`{7DD42A49-5329-4832-8DFD-43D979153A88}`) | TCP connect/accept/disconnect/retransmit, UDP send/recv **с удалённым адресом**, байты, PID | администратор (сессия ядра) |
| `Microsoft-Windows-TCPIP` | переходы состояний, RST, тайм-ауты рукопожатия | администратор |
| `Microsoft-Windows-DNS-Client` (`{1C95126E-7EEA-49A9-A3FE-A378B03DDB4D}`) | имя → ответ → PID процесса | пользовательская сессия реального времени, обычно администратор |
| `Microsoft-Windows-WinINet`/`WebIO` (опционально) | имена хостов HTTP(S) | — |

Реализация: `StartTraceW`/`EnableTraceEx2`/`OpenTraceW`/`ProcessTrace` через
крейт `windows`; разбор через TDH (`TdhGetEventInformation`) или фиксированные
схемы событий версии ОС; буфер событий → агрегатор в потоке сборщика →
`TickBatch` (UI по-прежнему получает данные не чаще 1 раза в секунду).
Сохраняются только метаданные: адреса, порты, PID, размеры, флаги; не
содержимое.

### Привилегии

UI остаётся без прав. Для сессии ядра — **отдельная служба `ni-etw-helper`**,
устанавливаемая только по явному согласию:

- команды: `Hello`, `StartCapture { pids[], providers[] }`, `StopCapture`,
  `Drain { since }`, `Status` — без путей, без shell, без произвольных провайдеров
  (только белый список выше);
- именованный канал с `PIPE_REJECT_REMOTE_CLIENTS`, DACL «SYSTEM + интерактивный
  пользователь», проверка образа клиента, лимит кадра 1 МБ, лимит событий в
  буфере, автоостановка сессии ETW при отключении клиента;
- без службы приложение работает как в 0.1 и явно сообщает, что событийный сбор
  недоступен.

## 2. WFP (наблюдение, не фильтрация)

`FwpmNetEventSubscribe` — события отброса пакетов фильтрами WFP (локальный
брандмауэр/антивирус). Позволяет отличить «отброшено локально» от «нет ответа из
сети». Только чтение; правила WFP не создаются.

## 3. Расширение модели

- `EndpointRecord`: `dnsName`, `bytesSent/Received`, `packets`, `rttMs`,
  `retransmissions`, `resets` (+ источник каждого поля); `serde(default)`, новая
  миграция `endpoint_metrics`.
- События: `tcpConnectAttempt`, `tcpRetransmit`, `tcpReset { direction }`,
  `udpDatagram { remote, bytes }`, `dnsQuery { name, answers, status }`,
  `wfpDrop { layer, filterId }`; `EVENT_SCHEMA_VERSION = 2`.
- ASN/владелец сети — из локальной офлайн-базы (без запросов к API), с указанием
  даты базы.

## 4. DPI Detection Engine

Правила переходят из «запланировано» в «работает» только с нужными данными:

| Правило | Данные | Наблюдение | Основная альтернатива |
|---|---|---|---|
| `tcp.reset_anomaly` | ETW TCPIP | RST вскоре после ClientHello, повторяемо, при успешном рукопожатии | сервер отклоняет TLS, локальный антивирус |
| `tls.handshake_disruption` | ETW + TLS-проверка | рукопожатие TCP прошло, TLS обрывается/зависает на 1-м пакете | MTU/фрагментация, прокси |
| `sni.filtering` | активная TLS-проверка | один IP: SNI A — обрыв, SNI B (контрольный) — успех | виртуальный хостинг, политика сервера |
| `ip.filtering` | проверки + ETW | все порты IP недоступны, соседние IP той же сети доступны | падение сервера, маршрут |
| `dns.filtering` | DNS-Client + контрольный резолвер (DoH по выбору пользователя) | системный и контрольный ответы различаются систематически | гео-DNS, CDN |
| `udp.response_anomaly` | ETW UDP | исходящие датаграммы есть, входящих нет ни от одного адреса набора, при этом TCP к тем же узлам работает | сервер не отвечает, NAT |
| `throttling` | ETW байты/повторы | скорость падает до фиксированного потолка после N КБ при нормальном RTT | перегрузка канала |

Общие требования: каждый вывод содержит контрольное измерение; уверенность в
DPI не выше «средней» без двух независимых признаков; «доказано» не
используется никогда. Активная TLS-проверка — только к выбранной цели, только
ClientHello с указанным SNI, без отправки данных приложения.
